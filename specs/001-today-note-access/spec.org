#+TITLE: W001 - Open one fixed note from command and icon
#+STARTUP: overview

* Summary

- *Outcome* :: A user selects one fixed Markdown note and opens it through an
  Obsidian command/hotkey or in-app icon.
- *Before* :: The plugin exposed a configuration shell and a placeholder
  notice.
- *After* :: The plugin provides note selection, persisted configuration,
  opening, unavailable-target status, and settings back navigation.
- *Unchanged boundary* :: The plugin does not create or edit note content and
  has no network, telemetry, date logic, or Node/npm runtime dependency.
- *Evidence state* :: Static checks pass; host interaction is recorded PASS by
  user validation on 2026-09-16, without device or version coverage detail. See
  [[file:validation.org][W001 - validation record]].
- *Next step* :: Record the closure decision.

* Context and scope

The plugin provides quick access to one user-selected, undated Markdown file in
the current Obsidian vault. The filename remains fixed until the user selects a
different file.

In scope:

- selecting one Markdown file through an Obsidian searchable file picker;
- storing the selected file path in plugin data;
- opening the selected file through the command/hotkey and ribbon icon;
- showing a red warning icon when the configured target is unavailable; and
- providing a Back button inside the plugin settings view.

Out of scope:

- Obsidian Daily Notes or date-based lookup;
- note creation, renaming, templates, or content mutation;
- multiple configured notes;
- operating-system widgets, URL schemes, synchronization, network access, or
  telemetry; and
- Node.js/npm build or runtime dependencies.

* Requirements

** FR-001 - select and persist one target note

The settings view shall let the user search the current vault's Markdown files,
choose one file, and persist its vault path in plugin data. Clearing the choice
shall leave no configured target.

** FR-002 - open the configured target

When a configured target resolves to a Markdown file, the command exposed to
Obsidian shall open that file in Obsidian's standard workspace interface.

** FR-003 - provide the same action from the ribbon icon

The in-app ribbon icon shall invoke the same target-opening action as the
command. It shall be available on macOS and iOS through Obsidian's interface.

** FR-004 - expose unavailable-target state

When the configured path is empty or does not resolve to a Markdown file, the
ribbon icon shall use a red warning state and the plugin shall not create or
modify a replacement note.

** FR-005 - return from plugin settings

The plugin settings view shall provide a Back button that returns the user to
Obsidian's settings navigation.

** FR-006 - preserve the minimal offline boundary

The plugin shall contain no Node.js/npm runtime or build artefact dependency,
no network or telemetry behaviour, and no direct filesystem access outside
Obsidian's public vault APIs.

* Solution design

=main.js= uses Obsidian's public ~FuzzySuggestModal~ to present Markdown files,
~getAbstractFileByPath~ and ~TFile~ to resolve the selected target, and
~WorkspaceLeaf.openFile~ to open it. The command and ribbon icon share one
opening method. Vault lifecycle events refresh the warning state. The settings
Back button is a native control in ~PluginSettingTab.containerEl~ that closes
the host settings controller.

=styles.css= provides only the red unavailable-target state. The installer is a
separate Bash copy operation and does not compile or bundle the plugin.

* Delivery handoff

The accepted implementation is in =main.js=, =styles.css=, and
=scripts/install.sh=. No automated browser harness or persistent behavioural
test suite is justified for this small host-specific feature. The host tests
are established by user validation on macOS and iOS.
