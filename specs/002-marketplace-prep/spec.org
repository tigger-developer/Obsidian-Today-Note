* Compatibility and design

** AC002.3 - attest only matching installation files :ac:
:PROPERTIES:
:CUSTOM_ID: ac002-3
:END:

Each master push increments the patch version and publishes the three
installation files. Automatic or manual attestation signs only those files
after verifying their version, exact asset set, and byte equality with checkout
and tag. Attestation does not modify the release or attach extra files.
Covered by [[#ot002-3][OT002.3 - attestation workflow checks]].

** Attestation boundary

The workflow uses job-scoped =contents: read=, =id-token: write=, and
=attestations: write=. Checkout credentials are not persisted. The reference
workflow's pinned checkout and attest actions are reused. Attestations are
stored by GitHub separately from release attachments; storage-record creation
is disabled. Hosted-runner temporary storage holds downloaded comparison files.

The current =1.0.1= manifest attachment was updated after tagging at the
operator's request. It differs from the tagged manifest description and must
be rejected. Resolving that discrepancy requires a subsequent release or an
explicitly authorized tag change, not a weakened comparison.

** Existing installation compatibility

The new ID uses a new plugin directory and command namespace. Existing local
users disable the old installation, enable the new one, select the note, and
assign the hotkey again. The installer does not migrate or delete old settings.
The source entry point and stylesheet remain unchanged. There are no new
dependencies, network calls, note writes, or access permissions.
